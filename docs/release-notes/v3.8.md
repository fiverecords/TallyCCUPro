## TallyCCU Pro v3.8 — Full code audit: live stability, tally fixes & hardening

> ⚠️ **This version has a bug and does not compile** with the official Blackmagic `BMDSDIControl` library (`no matching function for call to ... writeCommandInt8(..., const int8_t [2])`). **Use [v3.8.1](https://github.com/fiverecords/TallyCCUPro/releases/tag/v3.8.1) instead**: it fixes the build and has all the changes listed below, with the same behaviour on the cameras, tally and Companion.

This release is the result of a full audit of the codebase (firmware, web interface, serial configurator and documentation; 235 verified findings, see [`docs/AUDITORIA-v3.7.1.md`](https://github.com/fiverecords/TallyCCUPro/blob/v3.8/docs/AUDITORIA-v3.7.1.md)). It focuses on what matters on air: tally that is always right, an Arduino that never freezes or reboots because of the network, and camera values that nobody chose never reaching the camera.

**Compatible with the current Bitfocus Companion module (v3.1.0) without any change to the module** — checked with differential tests that drive the real, unmodified module against v3.7.1 and v3.8 (1507 cases, 0 regressions).

---

### 🔴 Critical Fixes

- **Tally only worked for vMix inputs 1-10** — inputs 11 and up never lit the tally, even though the tally page accepted them. Any mapped input up to 63 now works.
- **Several inputs on one camera overwrote each other** — a camera on air could show green. States are now combined and program wins over preview.
- **Tally stuck ON after vMix disconnect** — the 3.7.1 changelog claimed this fix but it was not in the code. Tally now turns off when vMix is lost, disabled or its IP changes, and a vMix that disappears without closing the connection is detected within ~15 s (heartbeat).
- **Watchdog reboots on air** — a browser, Companion or download client that vanished (Wi-Fi drop, laptop asleep) could freeze the Arduino and trigger a watchdog reset. All network I/O is now non-blocking or time-bounded.
- **Tally froze while the web page loaded** — serving the 195 KB page blocked the loop for seconds. Tally keeps updating during transfers (under 100 ms in tests), and pages can be served gzip-compressed.
- **Values nobody chose reached the camera** — exponent values from Companion (e.g. `2.7e-17`) were applied as huge numbers; loading a preset re-ran auto white balance / autofocus; web presets sent never-read defaults such as UHD 60p video mode, iris 0 and focus 0.
- **Stale vMix socket** — after a refused vMix connection the firmware kept a socket the web server or Companion could reuse.
- **Out-of-bounds stack write** — malformed tally map keys in a request could write past a stack buffer.

### 🟡 Medium Fixes

- PTZ joystick and continuous zoom: one request in flight, stop retried, Pointer Events; optional safety stop (deadman) for the web interface only.
- Preset save/load report the real result (no more "saved ✓" on failure); saves and uploads are atomic.
- Two browsers no longer kick each other off the real-time sync (2 SSE clients).
- Port 8098: proper line handling, large Companion sync dumps processed without blocking, idle connections reclaimed; Companion's `timecode_source` action now reaches the camera.
- Safe Mode: no I2C writes to the uninitialized shield; automatic exit when the shield answers again; boot-loop detection covers the first 20 s of operation; `/reboot` and serial `reset` no longer count as boot failures.
- Boolean `true` was applied as false; fixed-point 16.0 wrapped to -16.0.
- Blank EEPROM booted with tally/CCU overrides OFF.
- SD card failures are reported and the card is remounted automatically.
- Serial configurator no longer resets the Arduino when it connects (where the OS allows it).

### 🟢 Minor Fixes & Improvements

- Static RAM down from ~6.1 KB to ~3.5 KB (parameter table and fixed strings moved to flash).
- Verbose serial logs on hot paths behind `DEBUG_HOT`.
- README: I2C bridge wiring corrected (A4 → SDA / pin 20, A5 → SCL / pin 21), connection limits and TCP protocol documented.
- Builds on Linux/macOS/CI (`#include` case fix); sketch folder now matches the `.ino` name.

### 🛡️ Hardening & Web Interface

- **Background file transfers** — while a slow client downloads a page, camera commands, the API, tally and the PTZ stop are answered at once (a Companion-style PTZ stop reaches the camera in about 10 ms in tests). Up to 2 transfers run at a time; a third waits for a slot, or gets `503` after 10 s when sockets are short.
- **Tally in the web interface** — the camera buttons show program (red) and preview (green) from vMix, and loading a preset, changing the video format or resetting to defaults on a camera that is on air asks first.
- **Per-camera state in the web interface** — knobs, sliders, color wheels and multi-value parameters no longer carry over from one camera to another; values not known for a camera are shown as unknown, and presets and Reset to Defaults only send known values (never the video format, actions, color bars or the lens position on reset).
- **Tally, CCU and vMix buttons stay in sync** with other browsers and Companion; a click acts on the state TallyCCU reports.
- **CSRF protection** — requests that change settings or files need the header `X-TallyCCU: 1` (the pages send it; the Companion module is not affected), and no response carries `Access-Control-Allow-Origin: *` any more. **Own scripts must add the header**: see *Security* in the README.
- **SD Card Manager** — file names can no longer run scripts in the page; system pages and their `.gz` cannot be deleted or renamed, only replaced by an upload.
- Preset names with `&`, `%`, `+` or commas are kept exactly; malformed `%XX` sequences and cut requests are rejected; JSON and port 8098 lines are escaped.
- The value echoed to Companion and the browsers is what the camera received (for example `0,0` for an empty field); with the CCU override off nothing is echoed as applied.
- Tally heals itself: every mapped camera gets its tally again every 4 s and a shield that reset gets its settings back.
- Real reset cause (power on, reset button, restart, watchdog and where it hung) in `status` and the Safe Mode page; only hangs in the first 20 s count as boot failures. Safe Mode page also without the SD card.
- Serial console: `mac`, `factoryreset yes`, case-insensitive commands, over-long lines rejected; strict IP validation with cable / Ethernet chip reporting; EEPROM layout header.
- Finer iris, focus and zoom knobs that send while dragged; typed values are sent; shutter steps follow 50/60 Hz; preset IDs 0-4 as in Companion; destructive buttons set apart and confirmed; touch fixes.
- The firmware version lives only in `FIRMWARE_VERSION`; the serial configurator reads it from the board.
- Tests and CI without hardware (emulator, robustness scenarios, host unit tests, the official Companion module), pinned library versions, release workflow and a reproducible configurator `.exe`.

### Upgrade Instructions

1. Flash the Arduino sketch from the **`firmware/TallyCCUPro/`** folder (it was `Arduino/` before).
2. Copy the HTML files from `sdcard/` to your SD card (replace existing). **Recommended:** also copy the `.gz` files included in the zip (or generate them with `python3 tools/gzip_sdcard.py`); pages load about 5x faster.
3. Power cycle the device.

Update the firmware and the SD card files together: the web pages rely on the new firmware responses and send the `X-TallyCCU` header. Your network settings, tally map and presets are kept. If you use your own scripts, add `-H 'X-TallyCCU: 1'` to the requests that change settings or files (see *Security* in the README).

The firmware version shows as **3.8** in the serial monitor (`status`), the serial configurator and `/safemode-status`.
