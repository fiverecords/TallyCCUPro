🔍 Possible Causes
  • SDI Shield without 12V power The Blackmagic SDI Shield requires external 12V power. Without it, I2C communication hangs during initialization.
  • Invalid SDI input signal The shield only supports 1080p/1080i at 3G-SDI Level B. 4K signals, Level A, or other formats can cause the shield to freeze.
  • SDI cable disconnected during boot Some shield firmware versions don't handle missing input gracefully during initialization.
  • I2C bus conflict Another I2C device on the bus may be interfering with shield communication.
✅ How to Fix
  • Verify that the SDI Shield has 12V DC power connected (check the power LED on the shield)
  • Connect a valid 1080p or 1080i SDI signal at 3G-SDI Level B from your camera or video source
  • Check all SDI cable connections are secure
  • Once fixed, click "Restart Normal Mode" below to retry. If Safe Mode started after boot failures, the board also restarts in normal mode by itself once the SDI shield has answered on I2C for 30 s
🎛️ Actions
Staying in Safe Mode for now. Nothing is sent to TallyCCU: it simply keeps running as it is. Safe Mode is not stored: after a reset or a power cut the board tries a normal boot again, and if the fault is still there it takes about 3 failed boots to come back here. If Safe Mode started after boot failures, it also restarts in normal mode by itself once the SDI shield has answered on I2C for 30 s (5 minutes after an automatic attempt that failed, and no more attempts after two failures). To force Safe Mode on the next boot, use the serial command safemode.

Note: In Safe Mode, the SDI Shield is completely disabled. No SDI output is possible - this means no tally lights and no camera control commands will reach your cameras. Network connectivity and the web interface remain available for diagnostics: the vMix IP and the tally map can be changed in Tally Config and files in the SD Card Manager. The Arduino IP, mask and gateway are changed with the serial configurator.
